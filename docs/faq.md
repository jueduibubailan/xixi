# FAQ

## How do I start a task?

```bash
uv run vrpar start problems/<slug>/task.yaml
```

There is no root `task.yaml`; a bare `vrpar start` is an error.

## Where is the problem statement?

In `problems/<slug>/task.yaml` under `task.description`. The `task:` block only
has `name`, `slug`, `description`, `tips`.

## Where are the other settings?

In `problems/<slug>/litellm_config.yaml`: `llm`, `workspace`, `run`, `stages`,
`score`, `loop`.

## Does the pipeline parse plan.md?

No. The pipeline checks that `artifacts/analysis/plan.md` exists. Agents read the
plan and decide the scale, file names and code changes.

## What is `test_train.py`?

A 1 epoch × 64 episode training check generated by the `code_error` agent. It
saves POMO's `checkpoint-1.pt`.

## What is the score?

The last `AUGMENTATION SCORE:` line from `test_<n>.py`, which runs
`test_episodes = 10*1000` on random test data.

## What does success mean?

`test_train.py` contains the 1×64 pins, both exit codes are 0, and the final test
entry printed an `AUGMENTATION SCORE:` line.

## What is exported?

`workspace/final/<task.slug>/artifacts/generated/` plus the full `pomo/` tree.
No samples, no results, no `run.py`.

## Where do I put a new problem?

`problems/<slug>/`; optional `instance_gen/` and `grader/` are read-only inputs.
There is no `context.md`.
