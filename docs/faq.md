# FAQ

## How do I start a task?

```bash
uv run vrpar start problems/<slug>/task.yaml
```

There is no root `task.yaml`; a bare `vrpar start` is an error.

## Where is the problem statement?

In `problems/<slug>/task.yaml` under `task.description`. The `task:` block only
has `name`, `slug`, `description`, `tips`.

## Where are the other settings?

In `problems/<slug>/litellm_config.yaml`: `llm`, `workspace`, `run`, `stages`,
`score`, `loop`.

## Does the pipeline parse plan.md?

No. The pipeline checks that `artifacts/analysis/plan.md` exists. Agents read the
plan and decide the scale, file names and code changes.

## What is `test_train.py`?

A 200 epoch × 5000 episode training run generated by the `code_error` agent. It
saves POMO's `checkpoint-200.pt`.

## What is the score?

The last `AUGMENTATION SCORE:` line from `test_n<n>.py`, which runs
`test_episodes = 10*1000` on random test data.

The test set can be specified by `task.tips`; when it is, the entry loads that set
(and `test_episodes` is its size). Otherwise the random protocol above applies.

## What does success mean?

`test_train.py` contains the 200×5000 pins, both exit codes are 0, and the final test
entry printed an `AUGMENTATION SCORE:` line.

## What is exported?

`workspace/final/<task.slug>/artifacts/generated/` plus the full `pomo/` tree.
No samples, no results, no `run.py`.

## What is nn improve?

After the first acceptance run passes, the pipeline enters a parameter search:
up to `nn_improve.rounds` batches (3 by default), each with
`strategies_per_batch` strategies plus `mutations_per_batch` mutations. Every plan
changes exactly one parameter, is applied by `code_adjustment`, and is scored by
`code_error` with the `search` protocol (50×5000). A plan that beats the fixed
`initial_search_score` gets label 1 and its code is kept under
`artifacts/nn_improve/winners/`; a better one becomes the champion in
`artifacts/nn_improve/best/`. A batch with no winner stops the search. The champion
is re-run once with the `acceptance` protocol (200×5000), and the initial code is
exported instead if it does not beat the initial score. See
[`nn_improve.md`](nn_improve.md).

## Where do I set the search and acceptance budgets?

Under `nn_improve.search` / `nn_improve.acceptance` in `configs/default.yaml`, in
the bundle's `litellm_config.yaml`, or on the command line, e.g.
`nn_improve.search.train_epochs=20 nn_improve.rounds=1`.

## How do I fill the parameter-strategy section?

Either edit the `## 参数修改策略` block in
`src/vrpar/prompts/s5_nn_improve.md`, or point
`nn_improve.strategies_file` at a markdown/YAML file (recommended; no code change).
Leave it empty and the pipeline validates leniently: a mutation only has to explain
itself in `novelty`.

## Where do I put a new problem?

`problems/<slug>/`; optional `instance_gen/` and `grader/` are read-only inputs.
There is no `context.md`.
