# SSTRPVST 问题描述（对齐 arXiv:2308.14744）

> 本文档是**唯一权威口径**。生成代码时以本文档为准；与论文表述冲突时以论文为准，并在 plan 里注明。

## 1. 一句话定义

有一个仓库、$n$ 个待喷洒节点、$K$ 辆喷洒车（sprayer）和 **1 辆**补给车（tanker）。
喷洒车从仓库出发依次访问节点并喷洒肥料，罐空时由补给车在**某个节点**与它会合并加注；
目标是最小化「两类车的总行驶时间 + 总加注时间 − 总喷洒时间」。

## 2. 实例（pkl 内容）

`grader/data/sstrp_n25_uniform.pkl` 是一个 `list[dict]`，长度 1000（固定种子 2025 生成）。
每个 dict 的字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `n` | int | 待喷洒节点数（15–25） |
| `K` | int | 喷洒车数量（2 或 3） |
| `depot` | `[x, y]` | 仓库坐标，恒为 `[0.0, 0.0]` |
| `nodes` | `list[[x,y]]` | $n$ 个节点坐标，范围 $[0,100]^2$ |
| `q_min`, `q_max` | `list[float]` | 每个节点的施肥量下界/上界，满足 $q_{max}=2.5\,q_{min}$ |
| `Qs` | float | 喷洒车罐容（15.0） |
| `Qr` | float | 补给车罐容（52.5） |
| `xi` | float | 一次加注耗时（3.0） |
| `eta` | float | 单位肥料所需喷洒时间（2.0） |
| `beta` | float | 补给车相对喷洒车的速度倍数（2.0） |
| `speed_sprayer` | float | 喷洒车速度（20.0，用于把欧氏距离换成时间） |
| `speed_tanker` | float | 补给车速度（= beta × speed_sprayer，40.0） |
| `farm_side` | float | 农场边长（100.0），仅作记录 |

**重要**：所有参数都从实例里读，**不要重新采样**。

距离与时间换算：

$$
\text{travel\_time} = \frac{\lVert x_i-x_j\rVert_2}{\text{speed}}
$$

## 3. 决策

1. 每辆喷洒车 $k$ 的节点访问序列（一条路线，起止于仓库）；
2. 每次访问的施肥量 $u_i\in[q_{min,i},\,q_{max,i}]$；
3. 哪些访问后需要加注（$\delta_i\in\{0,1\}$）；
4. 补给车的节点访问序列（一条路线，起止于仓库），其访问集合必须等于 $\{\,i:\delta_i=1\,\}$；
5. 每次加注的量 $v_i$。

## 4. 目标函数

$$
\min\;\;
\underbrace{\sum_{\text{所有车辆}}\sum_{\text{相邻节点}} \text{travel\_time}}
_{\text{两类车总行驶时间}}
\;+\;\underbrace{\xi\sum_{i}\delta_i}_{\text{总加注时间}}
\;-\;\underbrace{\sum_{k}\sum_{i} s^k_i}_{\text{总喷洒时间}}
$$

其中 $s^k_i=\eta\cdot u^k_i$。

注意：第三项是**负的**，所以目标值可能为负；施肥越多目标越好，但受 $q_{max}$ 与补给能力约束。**目标值越小越好。**

## 5. 约束（逐条可检查）

1. **覆盖唯一性**：每个节点被且仅被一辆喷洒车访问一次。
2. **路线闭合**：每辆喷洒车的路线从仓库出发、最终回到仓库；补给车同理。
3. **喷洒车容量**：任意时刻罐内肥料 $0\le \ell\le Q_s$；喷洒前必须有 $\ell\ge u_i$。
4. **加注时点**：加注只能发生在**该节点喷洒完成之后**，即加注开始时刻 $\theta_i = y_i + s_i$，其中 $y_i$ 是到达时刻。
5. **喷洒车不等待**：喷洒车的等待时间恒为 0（等价于：加注在喷洒完成后立即开始，喷洒车不提前等补给车）。
6. **补给车同步**：补给车到达加注节点的时刻 $w_i \le \theta_i$（早到可以等，晚到不可行）。
7. **补给车容量**：$0\le h\le Q_r$，且单次加注量 $v_i\le$ 当时罐内余量；加注后喷洒车罐内 $\le Q_s$。
8. **施肥量区间**：$q_{min,i}\le u_i\le q_{max,i}$。
9. **服务时间**：$s^k_i=\eta\cdot u^k_i$。
10. **补给车只停加注点**：补给车的访问集合 $=\{\,i:\delta_i=1\,\}$，且每个加注点只被访问一次。

## 6. 解的形式

对每个实例，解包含：

```
K 条喷洒车路线：每条是节点索引序列（不含仓库，仓库隐含在首尾）
每次访问的 u（施肥量）与 δ（是否加注）
1 条补给车路线：节点索引序列（只含加注点）
每次加注的 v（加注量）
```

## 8. 必须先定的三个建模选择（会影响与论文的可比性）

1. **$u$ 怎么定**。论文里 $u$ 是连续决策。POMO 解码器若无法输出连续值，建议在
   $\{q_{min},\ (q_{min}+q_{max})/2,\ q_{max}\}$ 三档中选（每个访问位置加一个 3 分类头）。
   **若固定成 $q_{min}$，问题就退化了**，必须在论文里写明"我们固定施肥量下界"。
2. **$Q_r$**。论文只给加仑区间（4000–6000 vs 1300–1600），未给"单位"值；本 bundle 取 $3.5Q_s$。
   换别的比例会改变可行性，必须在论文里写明。
3. **坐标尺度 / 速度**。论文只给英亩面积，未给坐标范围；本 bundle 用 $[0,100]^2$ 与 speed=20。
   这个选择决定"行驶时间 vs 喷洒时间"的相对权重，是**最影响结果**的自由参数。
