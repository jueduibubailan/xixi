# VRPLTW 问题描述

**Vehicle Routing Problem with Duration Limit and Time Windows**
**带时长限制与时间窗的车辆路径问题**

| 项目 | 内容 |
|---|---|
| 缩写 | VRPLTW（亦写作 VRPTW-DL、VRPTW with route duration limit） |
| 约束组合 | **C + L + TW**：容量（Capacity）+ 时长限制（Duration Limit）+ 时间窗（Time Window） |
| 问题族 | 车辆路径问题（VRP），NP-hard |
| 参照定义 | MVMoE（ICML 2024）第 3 节、附录 A *Setups of VRP Variants* 与 Table 3 |
| 文档性质 | 仅问题描述（不含求解算法、不含代码实现） |

---

## 1. 一句话定义

> 在容量受限的车辆路径问题（CVRP）之上，同时施加两类时间相关约束：**(i)** 每个客户必须在其时间窗 $[e_i,l_i]$ 内开始服务，早到需等待；**(ii)** 每辆车从离开配送中心到返回配送中心，其路径总长度（车速为 1 时即行驶时间）不得超过上限 $L$。在满足全部约束的前提下，用若干辆车服务所有客户，使总行驶距离最小。

---

## 2. 背景与问题定位

### 2.1 现实背景

城市配送中，一辆车一天的工作时长受劳动法规与排班限制（对应 **L**），而客户只在特定时段收货、门店只在营业时间接货（对应 **TW**），同时车辆载重有限（对应 **C**）。三者叠加是最常见的实际配送形态：车辆既不能"迟到"，也不能"跑太久"，还不能"装太多"。

### 2.2 在 VRP 变体谱系中的位置

MVMoE 以 CVRP 为基座，用 5 类约束（C、O、B、L、TW）组合出 16 个变体。VRPLTW 是其中**同时选中 C、L、TW** 的三约束变体（不选 O 开放路径、不选 B 回程取货）：

| 变体 | C | O | B | L | TW |
|---|---|---|---|---|---|
| CVRP | ✓ | | | | |
| VRPL | ✓ | | | ✓ | |
| VRPTW | ✓ | | | | ✓ |
| **VRPLTW** | **✓** | | | **✓** | **✓** |
| OVRPLTW | ✓ | ✓ | | ✓ | ✓ |
| VRPBLTW | ✓ | | ✓ | ✓ | ✓ |
| OVRPBLTW | ✓ | ✓ | ✓ | ✓ | ✓ |

> 注：在 MVMoE 中 VRPLTW 不在训练集内（训练集仅含 CVRP、OVRP、VRPB、VRPL、VRPTW、OVRPTW），属于 10 个**零样本（zero-shot）**测试变体之一，用于检验模型对"未见过的约束组合"的泛化能力。

### 2.3 组合约束的非平凡性

约束叠加**不是简单相加**：每条约束的判定式会随其他约束是否启用而改变。例如

- **O + L**：车辆不返回 depot，长度判定去掉回程边，只要求 $l_t+d_{ij}\le L$；
- **O + TW**：车辆不返回 depot，回程时限 $l_0$ 整体失效；
- **L + TW**（本问题）：两者**同时生效**，长度判定仍含回程边 $d_{j0}$，时间判定仍含 $l_0$，形成"双重挤压"。

## 3. 输入实例

### 3.1 实例组成

一个 VRPLTW 实例由以下要素构成：

| 要素 | 记号 | 说明 |
|---|---|---|
| 配送中心 | $v_0$ | 唯一，坐标为 $y_0\in[0,1]^2$ |
| 客户集合 | $C=\{v_1,\dots,v_n\}$ | $n$ 为客户数 |
| 客户坐标 | $y_i\in[0,1]^2$ | 与 depot 同分布，独立均匀采样 |
| 客户需求 | $\delta_i$ | 整数 $1\ldots9$ |
| 车辆容量 | $Q$ | 标量，随 $n$ 取值（见 3.3） |
| 路径长度上限 | $L$ | 标量，默认 $L=3.0$ |
| 客户服务时间 | $s_i$ | 默认恒为 $0.2$；depot 服务时间为 0 |
| 客户时间窗 | $[e_i,l_i]$ | 由 3.2 的规则生成，落在 $[0,3]$ 内 |
| depot 时间窗 | $[e_0,l_0]$ | 固定为 $[0,3]$ |
| 车辆速度 | $v$ | 归一化为 1，故"距离 = 行驶时间" |

### 3.2 数据生成规则（MVMoE 标准设置）

**坐标**：$y_0\sim U(0,1)^2$，$y_i\sim U(0,1)^2$，相互独立。

**需求**：$\delta_i\sim \text{Uniform}\{1,2,\dots,9\}$，等概率。送入神经网络前按 $\delta_i'=\delta_i/Q$ 归一化；求值/约束判定使用原始整数需求。

**服务时间**：$s_i=0.2$（常数），$s_0=0$。

**depot 时间窗**：$[e_0,l_0]=[0,3]$。

**客户时间窗**（对每个客户独立生成）：

1. 计算 depot 到客户的往返行驶时间 $d_{0i}=d_{i0}=\lVert y_i-y_0\rVert_2$（速度 1）；
2. 采样时间窗中心
   $$\gamma_i\sim U\big(\min(d_{0i},\,2.8-d_{0i}),\ \max(d_{0i},\,2.8-d_{0i})\big),$$
   即中心落在 $d_{0i}$ 与 $l_0-d_{i0}-s_i=2.8-d_{0i}$ 之间；
3. 采样半宽
   $$h_i\sim U\!\left(\frac{s_i}{2},\ \frac{l_0}{3}\right)=U(0.1,\ 1.0);$$
4. 截断得到时间窗
   $$e_i=\mathrm{clamp}(\gamma_i-h_i,\ 0,\ 3),\qquad l_i=\mathrm{clamp}(\gamma_i+h_i,\ 0,\ 3).$$

该生成方式源自 Li et al. (2021b)，思想与 Solomon (1987) 的基准算例一致："以 depot 可达时段为基准、叠加随机宽度"，比纯人工构造更接近实际，也更难。

**实例合法性检查**：生成后逐客户验证"depot → 该客户 → depot"这一最简单路径是否时间可行，即
$$\max(d_{0i},\ e_i)+s_i+d_{i0}\ \le\ l_0=3 .$$
只要有一个客户不满足，整批实例重新生成。此检查保证每个实例至少存在可行解。

### 3.3 规模与参数

| $n$ | 容量 $Q$ | $L$ | $s_i$ | depot 时间窗 | 备注 |
|---|---|---|---|---|---|
| 20 | 30 | 3.0 | 0.2 | [0, 3] | 小规模 |
| 50 | 40 | 3.0 | 0.2 | [0, 3] | 常用 |
| 100 | 50 | 3.0 | 0.2 | [0, 3] | 常用 |
| 200 | 70 | 3.0 | 0.2 | [0, 3] | 大规模 |

> 容量随 $n$ 增大而增大，是为了让"平均每车服务客户数"保持在与实际配送相近的水平（需求均值 5，$Q=50$ 时约 10 个客户/车）。

### 3.4 实例规模估计

- 决策空间：把 $n$ 个客户划分为若干有序子序列，规模为 $O(n!\cdot 2^n)$ 量级；
- 单车容量约束下，一条路径的客户数上界约为 $\lfloor Q/\bar\delta\rfloor\approx Q/5$；
- 长度约束 $L=3$ 进一步限制单条路径的跨度：在单位正方形内，一条长度 3 的路径通常只能覆盖 6–10 个客户（取决于分布）。

## 4. 解的表示与决策内容

### 4.1 解的形式

一个解 $\tau$ 是若干条**路径（route / sub-tour）**组成的有序列表：

$$\tau=(r_1,r_2,\dots,r_m),\qquad r_k=(v_{k,1},v_{k,2},\dots,v_{k,n_k}),$$

其中每条路径隐含首尾为 depot：

$$v_0\to v_{k,1}\to v_{k,2}\to\cdots\to v_{k,n_k}\to v_0 .$$

- 所有路径的客户集合构成 $C$ 的一个**划分**（每个客户恰好出现一次）；
- 路径条数 $m$ 是**决策变量**，不预先固定，上界为 $n$（每车只服务一个客户）；
- 路径内部的访问顺序是决策变量；
- 不允许空路径（$n_k\ge1$）。

### 4.2 需要决策的三件事

1. **分组**：哪些客户由同一辆车服务；
2. **排序**：每辆车按什么顺序访问其客户；
3. **派车数**：总共派出多少辆车（间接由分组决定）。

### 4.3 距离与成本

两节点间距离取欧氏距离：

$$d_{ij}=\lVert y_i-y_j\rVert_2=\sqrt{(x_i-x_j)^2+(y_i-y_j)^2}.$$

一条路径的长度：

$$D(r_k)=\sum_{t=0}^{n_k} d_{v_{k,t},\,v_{k,t+1}},\qquad v_{k,0}=v_{k,n_k+1}=v_0 .$$

---

## 5. 约束条件

一条路径 $r=(v_0,i_1,i_2,\dots,i_k,v_0)$ 必须同时满足以下四组约束。

### 5.1 结构约束（覆盖与闭合）

- **覆盖**：每个客户恰好属于一条路径，且在该路径中出现一次；
- **闭合**：每条路径从 $v_0$ 出发并返回 $v_0$（与 OVRP 的区别所在）；
- **非空**：每条路径至少服务一个客户。

### 5.2 容量约束（C）

路径上所有客户需求之和不超过车辆容量：

$$\sum_{t=1}^{k}\delta_{i_t}\ \le\ Q .$$

容量在路径开始时为 $Q$，每访问一个客户扣减 $\delta$，剩余容量不足时该客户不可加入。

### 5.3 时长限制（L）——本问题的关键约束

每条路径的**总行驶长度**不超过上限：

$$D(r)=\sum_{t=0}^{k} d_{i_t,\,i_{t+1}}\ \le\ L=3.0,\qquad i_0=i_{k+1}=v_0 .$$

**口径必须明确**（这是本问题最容易出错的地方）：

| 口径 | 表达式 | 是否 MVMoE 的实现 |
|---|---|---|
| **纯行驶长度**（本文采用） | $\sum d_{ij}\le L$ | ✅ 是 |
| 行驶 + 服务 | $\sum d_{ij}+\sum s_i\le L$ | ❌ 否 |
| 行驶 + 服务 + 等待（在途总时长） | $t^{\text{return}}-t^{\text{depart}}\le L$ | ❌ 否 |

MVMoE 的参考实现（`VRPLTWEnv`）中，`length` 只累加相邻节点间的欧氏距离，到达 depot 时清零；服务时间 $s_i$ 只在时间窗递推中使用，**不计入** $L$。因此在 $L=3$、$s_i=0.2$ 时，一条含 8 个客户的路径若按"工时"口径计算会多出 $1.6$，两种口径的判定结果可能完全相反。

> 由于车速归一化为 1，"长度"与"行驶时间"在数值上相等，故论文称之为 duration limit；但它是**行驶时长**，不是含服务的在岗时长。

### 5.4 时间窗约束（TW）

记车辆到达客户 $v_i$ 的时刻为 $a_i$，开始服务时刻为 $t_i$。

- **早到等待**：
  $$t_i=\max(a_i,\ e_i);$$
- **服务窗口**：必须在关闭前开始服务
  $$e_i\ \le\ t_i\ \le\ l_i ;$$
- **服务时长**：服务结束后才能离开，离开时刻为 $t_i+s_i$；
- **时间递推**：沿路径依次计算
  $$a_{i_{t+1}}=t_{i_t}+s_{i_t}+d_{i_t,i_{t+1}},\qquad t_{i_{t+1}}=\max(a_{i_{t+1}},e_{i_{t+1}});$$
- **回程时限**：所有车辆必须在 depot 关闭前返回
  $$t_{i_k}+s_{i_k}+d_{i_k,0}\ \le\ l_0=3 .$$

depot 的出发时刻取 $t_0=0$（也可视为 $t_0\in[e_0,l_0]$，但由于 $e_0=0$ 且越早出发越有利，最优解总可取 $t_0=0$）。

**不允许**：迟到后"罚分继续服务"、把服务推迟到窗口之后、或忽略等待直接跳到下一客户。

### 5.5 三条约束的耦合关系

- **C 与 L 独立**：一个限制"装多少"，一个限制"跑多远"，互不替代；重货可能装不满就超重，轻货可能装得下但跑太长。
- **TW 与 L 同向挤压**：二者都在压缩单条路径可容纳的客户数，但同时生效时可行域呈"剪刀差"——等待会消耗时间窗余量却不消耗长度余量，绕行会消耗长度余量却可能换来时间窗可行。
- **TW 与 C 弱相关**：容量只影响能装多少客户，不直接影响时刻。
- **L 与 TW 的冲突点**：某些客户单独看时间窗可行、长度也可行，但"接入后剩余长度不足以返回 depot"或"返回时超过 $l_0$"，此时必须开新路径。

## 6. 目标函数

在所有可行解中最小化**总行驶距离**：

$$\min_{\tau\in\Phi}\ c(\tau)=\sum_{k=1}^{m} D(r_k)=\sum_{k=1}^{m}\ \sum_{t=0}^{n_k} d_{v_{k,t},\,v_{k,t+1}} .$$

其中 $\Phi$ 为满足第 5 节全部约束的可行解集合。

补充说明：

- **无车辆固定成本**：目标只计距离，不惩罚"多派车"；派车数由距离与约束自然决定（在单位正方形内，多开车通常增加总距离，故不会无限增车）。
- **无时间惩罚**：等待不产生成本，也不计入目标；目标与时间窗只通过"可行性"发生关系。
- **无装载/卸货顺序成本**：不考虑装箱、LIFO、重心等。

---

## 7. 可行性的完整形式化定义

设路径 $r=(v_0,i_1,\dots,i_k,v_0)$，定义其可行当且仅当以下全部成立：

**(A) 容量**
$$\sum_{t=1}^{k}\delta_{i_t}\le Q .$$

**(B) 长度**
$$\sum_{t=0}^{k} d_{i_t,i_{t+1}}\le L,\qquad i_0=i_{k+1}=v_0 .$$

**(C) 时间窗**（递推定义）

$$
\begin{aligned}
a_{i_1}&=d_{0,i_1}, & t_{i_1}&=\max(a_{i_1},e_{i_1}),\\
a_{i_{t+1}}&=t_{i_t}+s_{i_t}+d_{i_t,i_{t+1}}, & t_{i_{t+1}}&=\max(a_{i_{t+1}},e_{i_{t+1}}),\\
\end{aligned}
$$

并要求

$$e_{i_t}\le t_{i_t}\le l_{i_t}\quad(1\le t\le k),\qquad t_{i_k}+s_{i_k}+d_{i_k,0}\le l_0 .$$

**(D) 结构**：$1\le k$，且全部路径的客户集合两两不交、并集为 $C$。

整个解 $\tau$ 可行 $\iff$ 每条路径均可行。

### 7.1 判定伪代码（描述性）

```
function route_feasible(route, Q, L, depot_window, s, tw):
    load = 0
    length = 0
    time = 0                       # 当前节点的服务完成时刻（depot 处为 0）
    prev = depot
    for node in route:
        load += demand[node]
        if load > Q: return False
        length += d(prev, node)
        arrival = time + d(prev, node)
        start = max(arrival, tw_start[node])
        if start > tw_end[node]: return False
        time = start + s[node]
        prev = node
    length += d(prev, depot)
    if length > L: return False
    if time + d(prev, depot) > depot_end: return False   # 服务已完成，直接返程
    return True
```

注意：返程段的时间检查是 `time + d(prev, depot) ≤ l0`（`time` 已含服务时间），而长度检查是 `length + d(prev, depot) ≤ L`（不含服务时间）。

## 8. 构造式求解中的候选可行性判定（MVMoE 解码规则）

自回归构造解时，每步从当前节点 $v_i$ 选择下一个节点 $v_j$。候选 $v_j$ 必须同时通过以下判定（第 1 条为访问性检查，第 2–5 条为约束检查，任一不通过即不可选）：

| # | 名称 | 判定式 | 含义 |
|---|---|---|---|
| 1 | 未访问 | $v_j\notin$ 已访问集合 | 每个客户只服务一次 |
| 2 | 容量 | $\delta_j\le q$ | $q$ 为当前剩余容量 |
| 3 | 时间窗 | $\max(t+d_{ij},\,e_j)\le l_j$ | 能在关闭前开始服务 |
| 4 | 回程时限 | $\max(t+d_{ij},\,e_j)+s_j+d_{j0}\le l_0$ | 接入后还能按时回仓 |
| 5 | 路径长度 | $l_t+d_{ij}+d_{j0}\le L$ | 接入后还能在长度上限内回仓 |

其中 $t$ 为当前节点服务完成时刻，$l_t$ 为当前路径已累计长度，$q$ 为剩余容量。

**要点**：

- 第 5 条是**前瞻式**判定：假设接入 $v_j$ 后立即返回 depot，若这样都超长则禁止接入。它是**保守剪枝**（充分不必要）——某些"接入 $v_j$ 后再接一个顺路客户"的可行扩展会被误删。
- 该判定**只在构造解时**使用；作为问题定义，长度约束仍以第 5.3 节的整条路径判定为准。
- 数值容差：实现中取 $\varepsilon=10^{-5}$，超过阈值才判为不可行，避免浮点误差误杀。
- 当所有客户均已访问，车辆必须返回 depot 结束当前路径，并可在 depot 处"重置"长度、时间、载重，开始新路径。

## 9. 边界情形与常见误解

1. **L 不含服务时间**。$L=3$、$s_i=0.2$、路径 8 个客户时，"工时口径"为 $3+1.6=4.6$，早已超限，但按 MVMoE 定义仍然可行。写论文/做实验时必须声明采用哪种口径。
2. **等待计入时间、不计入长度**。早到等待会推后后续时刻、压缩 TW 可行域，但不会增加 $l_t$。这导致"时间紧但距离松"和"距离紧但时间松"两类路径并存。
3. **长度约束是整条路径的，不是单段的**。单段距离小于 $L$ 不代表可行；必须累计到返程。
4. **回程段必须计入长度**。闭合路径的 $d_{i_k,0}$ 属于路径长度；只有 OVRP（开放路径）才去掉。
5. **时间窗端点闭合**。$t_i=e_i$ 与 $t_i=l_i$ 均可行；判定用 $\le$ 而非 $<$。
6. **不允许空路径**。每条路径至少一个客户；"派车但不出车"没有意义。
7. **车辆数不固定**。$m$ 由解决定，上界 $n$；目标不含固定成本，因此不会为了"少派车"而牺牲距离。
8. **实例保证可行**。生成时已剔除"depot→单客户→depot"都不可行的实例，故每个实例至少有一个可行解（每客户单独一车）。
9. **$L$ 与规模相关**。$L=3$ 是针对 $[0,1]^2$、$n\le200$、$s=0.2$ 标定的；换用 Solomon/Gehring-Homberger 等真实算例须按"最大工时"重新设定。
10. **"时长"与"距离"在本题等价**，仅因速度归一化为 1；若速度不为 1，长度约束应写成 $\sum d_{ij}/v\le L$。

## 10. 与相近问题的区别

| 问题 | 与 VRPLTW 的差异 |
|---|---|
| **CVRP** | 无时间窗、无长度限制，仅容量 |
| **VRPL** | 有长度限制，但无时间窗 |
| **VRPTW** | 有时间窗，但路径可任意长 |
| **OVRPLTW** | 不要求返回 depot：长度判定去掉 $d_{j0}$，时间判定去掉 $l_0$ |
| **VRPBLTW** | 增加 backhaul（20% 客户为负需求，可混装、无先后序），每车首客户须为 linehaul |
| **OVRPBLTW** | 上述全部约束叠加 |
| **VRPSTW（软时间窗）** | 允许迟到并罚分；VRPLTW 是**硬时间窗**，迟到即不可行 |

## 11. 一个数值例子

**实例**：depot $v_0=(0.5,0.5)$，$Q=50$，$L=3.0$，$s=0.2$，depot 时间窗 $[0,3]$。

客户 A：$y_A=(0.6,0.9)$，$\delta_A=7$，时间窗 $[0.4,1.2]$；
客户 B：$y_B=(1.0,0.55)$，$\delta_B=5$，时间窗 $[1.1,1.8]$。

**距离**

$$
d_{0A}=\sqrt{0.1^2+0.4^2}=0.4123,\quad
d_{AB}=\sqrt{0.4^2+0.35^2}=0.5315,\quad
d_{B0}=\sqrt{0.5^2+0.05^2}=0.5025 .
$$

**路径 $r=(A,B)$ 的检查**

| 检查项 | 计算 | 结果 |
|---|---|---|
| 容量 | $7+5=12\le50$ | ✅ |
| 到达 A | $a_A=0.4123$，$t_A=\max(0.4123,0.4)=0.4123\le1.2$ | ✅ |
| 到达 B | $a_B=0.4123+0.2+0.5315=1.1438$，$t_B=1.1438\in[1.1,1.8]$ | ✅ |
| 回程时限 | $1.1438+0.2+0.5025=1.8463\le3$ | ✅ |
| 路径长度 | $0.4123+0.5315+0.5025=1.4463\le3$ | ✅ |

结论：路径可行，成本 $1.4463$。

**反例 1（长度不足）**：若 $d_{B0}=2.0$，则长度 $=0.4123+0.5315+2.0=2.9438\le3$ 仍可行；但若再接一个客户 C（$d_{BC}=0.8$，$d_{C0}=1.5$），则长度超限，C 必须另开路径。

**反例 2（回程超时）**：若 B 的时间窗为 $[2.5,2.8]$，则 $t_B=\max(1.1438,2.5)=2.5$，回程 $2.5+0.2+0.5025=3.2025>3$，B 不可接入该路径。

**反例 3（前瞻剪枝误杀）**：设当前 $l_t=2.2$，候选 $v_j$ 满足 $d_{ij}=0.3$、$d_{j0}=0.9$，则 $2.2+0.3+0.9=3.4>3$ 被剪掉；但若存在客户 $v_h$ 使 $d_{jh}=0.1$、$d_{h0}=0.2$，则路径 $i\to j\to h\to0$ 长度为 $2.2+0.3+0.1+0.2=2.8\le3$，实际可行。这说明构造期的前瞻判定比问题定义更严格。

## 12. 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 配送中心 | depot | 车辆出发与返回的节点 $v_0$ |
| 路径 / 子路径 | route / sub-tour | 一辆车从 depot 出发、服务若干客户、返回 depot 的闭环 |
| 时间窗 | time window $[e_i,l_i]$ | 允许开始服务的时间区间 |
| 早到等待 | waiting time | 到达早于 $e_i$ 时等待至 $e_i$ |
| 服务时间 | service time $s_i$ | 在客户处装卸货所需时间 |
| 时长限制 | duration limit $L$ | 单条路径允许的最大行驶长度/时间 |
| 容量 | capacity $Q$ | 单车最大载重 |
| 需求 | demand $\delta_i$ | 客户所需货物量 |
| 可行解 | feasible solution | 满足 C、L、TW 与结构约束的解 |
| 零样本变体 | zero-shot variant | 训练时未见过、测试时直接求解的变体 |

## 13. 小结

VRPLTW = **CVRP + 硬时间窗 + 单路径长度上限**。其问题描述可归结为四个方面：

1. **分组**：把 $n$ 个需求为 $\delta_i$ 的客户分成若干组，每组需求和 $\le Q$；
2. **排序**：为每组排一个访问顺序，使按"到达—等待—服务"递推的时刻始终落在各客户时间窗内，且不晚于 $l_0$ 返回 depot；
3. **限长**：每组路径的行驶总长度（不含服务时间）$\le L=3$；
4. **优化**：在全部可行方案中，使总行驶距离最小。
